Why it exists

Nobody turning an agent loose worries about parameter counts.

They worry: can it read my filesystem, can it run shell commands, where does my data go, what does it do without a human in the loop, and what does it phone home? AppFacts labels the body. ModelFacts labels the brain. AgentFacts labels the hands.

Configuration, not codebase. The same binary with a different tool config is a different agent. Label the shipped defaults; a wider host policy is a new file.

The golden rule: if it's subjective ("this agent is very careful") it doesn't belong here. If it's a declared configuration fact ("this file says approval is required before filesystem writes") it does. That declaration is not proof the host enforces it on every run. When a fact isn't public, the file says undisclosed.

  • Operators deciding whether to unclip an agent on a real workspace
  • Teams comparing leash length, reach, and egress across configs
  • Harnesses that need a structured rollup before attaching toolsets
  • Anyone who wants ToolFacts detail behind an agent-level summary

The format

Frontmatter you can validate. A label you can skim.

---
agent_facts_version: "0.1.0"
name: ForgeTrail Reference Agent
developer: Catalyst Forge
kind: cli-agent
status: active
license: Apache-2.0
version: "0.1.0"
model:
  binding: host-provided
tools:
  count: 31
  executes_shell: false
  browses_web: false
  toolsets:
    - https://toolfacts.dev/examples/forgetrail-mcp/TOOL_FACTS.md
reach:
  filesystem: scoped
  network: none
autonomy:
  level: reactive
  self_looping: false
memory:
  persistence: none
  location: undisclosed
egress:
  telemetry: undisclosed
  data_shared: undisclosed
generated:
  date: 2026-09-16
  generator: hand-authored
---

Spec document 0.1.0 - fields may still shift before 1.0. Files declare agent_facts_version (0.1.0 today) so tooling can evolve with them.

Actor vs instrument: an MCP server gets ToolFacts. The agent configuration that uses that server gets AgentFacts, with tools.toolsets pointing at the itemized label.

Same agent, two configurations

ForgeTrail MCP only versus the same agent when the host also grants workspace and shell.

MCP only

forgetrail-reference · version 0.1.0 · 2026-09-24. Attached capability: 31 ForgeTrail tools. Filesystem is a scoped read through the tracking-validation tool. Network none, no shell. Host model is host-provided. Host telemetry is undisclosed.

Question the label can answer: does this file attach workspace write tools? No. Question it cannot answer: will a specific host process enforce that boundary on every run?

Host workspace (illustrative)

forgetrail-host-workspace · same agent, wider host policy. Attached capability now includes workspace read-write and shell. Autonomy is supervised, with declared approval for writes and shell. That is configured intent, not proven enforcement.

The narrower label does not constrain this host. Tool count 33 is illustrative (31 ForgeTrail tools plus host workspace and shell). Host workspace tools are not given ToolFacts files here.

What this file describes

Bind the label to a configuration and a date, then regenerate when the toolset or permissions change.

Identify the subject with name, optional version, repository, and generated.date. Point tools.toolsets at the ToolFacts files you actually reviewed. A later tool add, host permission change, or model-binding change is a new configuration. An older review does not cover it.

There is no configuration digest in the current schema. A digest over a canonicalized config document is a separate proposal, documented with the suite provenance note. Do not treat this page as adding that field.

Validate one

Hand-author from the template. Label the shipped defaults, then point tools.toolsets at the ToolFacts file. The validator is the CI gate. 

# validate any AGENT_FACTS.md (CI-friendly exit codes)
cd agent-facts/validator && pnpm install
pnpm validate ../examples/forgetrail-reference/AGENT_FACTS.md
pnpm validate ../examples/*/AGENT_FACTS.md

Output is checked against agent-facts.schema.json (draft-07). Frontmatter is the sole source of truth. The Markdown body is the human label. Validation is structural checking, not proof of compliance in every run.

ForgeTrail's reference config is the dogfood exemplar. The hub Panel is a derived snapshot of a tool surface, not a live drift monitor, and this site is not a public directory of other people's agents.
